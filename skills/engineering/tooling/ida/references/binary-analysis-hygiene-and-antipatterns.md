# Binary Analysis Hygiene, Type Reconstruction, and Anti-Patterns

Senior engineering standards for systematic reverse engineering, type system propagation, and anti-pattern mitigation in IDA Pro.

## 1. Systematic Symbol and Architecture Recovery

When analyzing unfamiliar compiled binaries for debugging, interoperability, or legacy codebase recovery, apply an outside-in analysis strategy:

1. **Imports and Exports Triage**: Identify external operating system APIs, network libraries, and file IO calls.
2. **String Cross-References**: Trace references from human-readable strings (logging messages, error codes, configuration keys) to locate core business logic handlers.
3. **Control Flow Refinement**: Convert raw byte addresses (`loc_401200`) into descriptive semantic function names (`handle_connection_handshake`).

## 2. Type Reconstruction via C Declarations

Modern compilers strip struct layouts, leaving pseudocode with raw byte offsets (such as `*(DWORD *)(a1 + 32)`). Reconstructing structs restores readable field access across all related functions.

### Parsing C Declarations into Local Type Library

```python
import ida_typeinf

c_declaration = """
struct PacketHeader {
    unsigned int magic;
    unsigned short sequence;
    unsigned short payload_length;
    unsigned int checksum;
};
"""

type_library = ida_typeinf.get_idati()
result = ida_typeinf.parse_decls(type_library, c_declaration, None, ida_typeinf.HTI_DCL)
```

Applying the parsed struct type to a function parameter immediately propagates throughout the Hex-Rays decompiler, replacing raw pointer arithmetic with clear struct field references.

## 3. Critical Anti-Patterns to Avoid

- **Premature Querying Before Analysis**: Querying xrefs or function graphs while background auto-analysis is active yields incomplete dependency trees.
- **Dangling Database Leases**: Forgetting to call `close_database` leaves `.i64.lock` files on disk, blocking subsequent sessions from opening the database.
- **Unverified Pseudocode Trust**: Decompiler output is an abstraction generated by heuristic AST transformations; when analyzing subtle race conditions or memory alignment, always verify against raw disassembled assembly.
- **Blind Non-Transactional Renaming**: Renaming shared functions or global variables without inspecting cross-references breaks callers across the database.
